# 02 工作流 AI 约束

## 开工必读

依次读取根 `AGENTS.md`、本目录 `README.md`、目标源码路径沿途的全部 `AGENTS.md`，再按需求 ID 回读 `网站重构需求.md` 和追踪矩阵。先追踪真实登录、guard、controller、service 和 repository 调用链，不能用伪造 actor 直接调用内部方法来证明越权可达。

## 修改边界

- 只直接实现本工作流拥有的路径；订单、报价、价格和库存由 03 决定，商品发布与媒体权限策略由 01 决定，横向 adapter/任务/审计由 04 提供。
- `company_id` 必须从已认证 actor 解析。请求中的企业 ID 只能作为资源定位条件，并与 actor 范围再次比对。
- 申请状态和企业状态分别建模；身份、通知、表单历史不得因当前资料变化而改写。
- 不主动修改共享装配文件；确需集成时仅追加本工作流公开入口并保持 04 可审查。

## 验证重点

优先通过 HTTP 和真实 guard 覆盖匿名、普通用户、其他企业成员、暂停企业、低权限后台账号和重新认证过期等拒绝路径。并发邀请、重复提交、会话轮换和通知幂等必须使用真实应用入口验证。
