# WEMOVE 消费者前台第一阶段设计

## 目标

以 Git 提交 `82c91027a656c57b78486eb004417c5931c973ad` 为唯一工程基线，将 `新建文件夹` 下视觉原型中的消费者公开站、账户和购物车体验落地到现有唯一前端 `apps/storefront`。本阶段先形成一组可浏览、可响应式验收、可继续接 API 的真实 Next.js 页面；经销商中心和管理后台留到后续阶段。

## 已确认的输入

- 视觉参考来自 `_zip_review` 中 9 个压缩包解出的 HTML/PNG 原型。原型用于页面结构、色彩、间距、表单和卡片表现参考，不直接复制 Tailwind CDN HTML。
- 工程边界来自 `AGENTS.md`、`apps/storefront/AGENTS.md` 和 `apps/storefront/src/AGENTS.md`。
- 页面数据只能通过 `/api/v1` 和 `@wemo/contracts` 获取，不能依赖 `packages/database`。
- `82c9102` 的 catalog、auth、cart、orders 模块是前端集成依据；页面不得假设 `main` 后续重构中的接口仍然存在。
- 产品图、价格、库存、用户权限和订单状态以后端响应为准；原型中的 `{Value}`、`{Product}` 等占位符不能进入正式页面。

## 范围

### 本阶段页面

公开站：

- `/`：品牌首页、主视觉、产品分类入口、精选产品/内容入口、支持与经销商入口。
- `/products`：产品目录、搜索、分类/标签筛选、排序、分页或加载更多。
- `/products/[slug]`：产品详情、媒体、卖点、规格、年龄段、相关产品和加入购物车入口。
- `/search`：搜索表单、结果列表、无结果和错误状态。
- `/support`：支持入口、常见问题/联系入口；具体内容从内容接口读取，接口不可用时显示可解释的空状态。

账户：

- `/login`、`/register`、`/forgot-password`：表单、校验、提交中、失败和成功反馈。
- `/account`：账户概览和最近订单摘要。
- `/account/profile`：个人资料展示与编辑状态。
- `/account/addresses`：地址列表、空状态、编辑入口和删除确认状态。
- `/account/orders`、`/account/orders/[id]`：订单列表、分页/筛选、订单详情和错误状态。

购物车：

- `/cart`：游客/登录用户购物车、数量调整、删除、金额摘要和去结算入口。
- 空购物车、购物车请求失败、商品失效/库存变化提示必须有明确展示。

### 明确不包含

- 支付页面、支付供应商接入、物流跟踪、税费最终计算。
- 经销商门户、后台管理页面。
- 真实邮件发送内容和后端业务规则重写。
- 为了视觉演示而复制一套 mock API 或绕过 `/api/v1` 的数据库读取。

## 方案与选择

采用“按业务域重建真实页面”的方案：

1. 统一平台壳和视觉 tokens；
2. 按公开站、账户、购物车分 feature 建页面；
3. 以服务端首屏读取为默认，以客户端交互更新为补充；
4. 对尚未能提供真实数据的接口使用类型安全的展示回退，仅用于开发和空状态验收，不伪装成生产数据；
5. 页面之间先使用 Next.js 路由和 URL 查询参数完成跳转、筛选和分页。

静态 HTML 迁移被排除，因为会产生重复结构和无法稳定接入合同类型的局部实现。一次性先铺全量后台也被排除，因为会把公开站核心体验的验收推迟到所有角色完成之后。

## 信息架构与组件边界

### App Router 分区

在 `apps/storefront/src/app` 创建以下路由组：

- `(public)`：公开站共享 `PublicHeader`、`PublicFooter` 和 SEO metadata。
- `(account)`：账户页面共享 `AccountShell`，但路由组只负责布局，不承担权限安全边界。
- 根级 `/cart`：购物车需要同时支持游客和登录用户，使用公开站导航但显示购物车摘要。

API 权限和身份始终由服务端检查；客户端隐藏链接不能替代权限判断。

### Feature 模块

- `features/platform`：API 客户端、请求状态、SEO/analytics 事件名、全局壳和响应式导航。
- `features/public-site`：首页、产品目录、详情、搜索、支持，以及 ProductCard、FilterBar、ProductGallery。
- `features/account`：认证表单、账户壳、资料、地址、订单摘要/列表/详情。
- `features/commerce`：CartSummary、CartLineItem、QuantityControl、金额展示和购物车状态。

通用按钮、输入、状态提示、分页、表格/列表基础样式优先复用 `@wemo/ui`；只在消费者领域有意义的组件留在对应 feature。页面文件负责路由和装配，不承载大段业务渲染逻辑。

## 视觉落地规则

- 继承现有 `@wemo/ui` tokens 的明亮中性底色、墨色文字、coral/blue/lime 运动强调色；避免为不同页面另起颜色体系。
- 原型中的大面积图形、产品媒体和强 CTA 作为结构参考；正式产品媒体通过产品响应中的 `primary_image_url`/媒体字段渲染，缺图时使用有边界的媒体占位状态。
- 桌面、平板、手机使用同一信息架构。移动端导航转为可键盘操作的展开控件，列表转单列，金额摘要在小屏保持可读。
- 所有交互控件有可读 label、`focus-visible` 样式和明确禁用/提交中状态；动画尊重 `prefers-reduced-motion`。
- 不使用原型中的可见占位符文本；无法取得内容时显示“暂无内容/暂时无法加载”一类可解释状态。

## 数据与状态设计

### API 边界

新增一个前端 API 层，集中拼接 `/api/v1`、处理 JSON、保留 `request_id`，并在边界用 `@wemo/contracts` schema 解析。页面不得手写与后端冲突的 DTO，也不得直接 import 数据库包。

初始资源边界：

- catalog：公开产品列表、产品详情、分类和筛选选项；
- search：关键词查询；
- auth/identity：当前会话、登录、注册、找回密码；
- cart：当前游客/用户购物车、数量更新、删除；
- orders：当前用户订单列表和详情；
- content/support：公开支持内容，若 `82c9102` 尚未提供可消费的细节合同，则先以明确空状态承载。

接口路径和方法必须以 `82c9102` 实际 controller/contract 为准；若基线只有模块 README 或接口尚未实现，页面保留适配器和状态，不在前端擅自发明后端字段。

### 页面状态

每个页面至少覆盖：首屏加载、成功有数据、成功无数据、请求失败、未登录/无权限（适用时）、移动布局和键盘焦点。失败状态显示可复制的 `request_id`，同时提供返回、重试或登录入口。

筛选、搜索关键词、排序和分页写入 URL；短暂的抽屉、密码可见性、提交中状态留在组件内。购物车数量更新使用乐观反馈但以接口返回为准，失败时恢复并说明原因。

## SEO、可访问性与分析

- 公开首页、产品列表、产品详情、搜索和支持页使用 `generateMetadata`/静态 metadata；首屏主要标题、产品名和链接存在于服务端 HTML。
- 产品详情的 title、description、canonical 和 Open Graph 使用后端产品内容，缺失时回退到品牌默认值。
- 页面标题层级唯一且连续；图片有有意义的 alt，装饰图形标记为隐藏。
- 主要流程支持 Tab、Enter、Escape 和屏幕阅读器标签；颜色对比度满足常规文本可读要求。
- 只发送已约定的页面浏览、搜索、商品查看、加入购物车和认证结果事件；不在事件中记录密码、完整地址或支付信息。

## 测试与验收

每个领域先写测试再实现，优先覆盖纯数据映射、状态分支和 URL 参数序列化。第一阶段至少包括：

- `ProductCard` 缺图、长标题、无年龄段和不同状态展示；
- 产品列表筛选/排序/分页 URL 往返；
- 登录/注册表单必填、格式错误、提交中和 API 错误；
- 购物车数量更新、删除、空购物车和接口失败恢复；
- 订单列表空状态、详情错误和未登录入口；
- 全部页面 TypeScript 类型检查、生产构建和移动/桌面浏览器人工验收。

完成门槛：

```text
pnpm --filter @wemo/storefront typecheck
pnpm --filter @wemo/storefront test
pnpm --filter @wemo/storefront build
```

并逐页检查首屏无水平溢出、键盘焦点可见、移动导航可操作、失败状态不吞错、公开页面首屏文本可被服务端渲染。

## 视觉回归补充（2026-09-07）

经确认，本阶段页面的视觉源以压缩包中的 `kinetic_editorial/DESIGN.md` 和消费者页面截图为准。现有实现的路由、数据适配器、状态组件和交互行为保留，表现层回归到原稿的编辑型电商语言：

- 基础画布使用 `#FAF9F5` 暖白，结构底色使用 `#F2F2EE`/`#FFFFFF`；正文与主要 CTA 使用 `#142536` 深海军蓝。
- `#2766D7` Sport Blue、`#F2573F` Active Coral、`#C7DF37` Play Lime 只作为低比例强调，不在同一组件中无约束混用。

- 站点壳恢复轻量固定头部、多列页脚、低对比度结构线和 4-12px 轻圆角；页面区域使用摄影/产品媒体比例和白色内容卡片建立层次，避免装饰性大色块替代内容。
- 首页恢复生活方式主视觉、编辑型内容分区和产品集合；目录恢复标题指标、左侧筛选、三列商品卡和内容横幅；详情、账户、购物车沿用原稿的白卡/暖灰分区结构。
- 缺少媒体时只显示带边界的品牌占位，不把截图或静态原型内容当成正式商品数据。

## 后端连接约束补充

视觉调整不能绕过真实内容边界。商品、媒体、账户、订单和购物车继续分别通过 `apps/storefront/src/features/*/` 适配器请求 `/api/v1`，并在边界使用 `@wemo/contracts` schema 解析。后端响应中的名称、描述、媒体 URL、状态、金额和权限优先于任何预览值。

开发预览只在明确允许的环境变量下使用，且必须显示 preview/unavailable 标识；生产环境没有可用接口时显示受控空态或错误态。`82c9102` 当前购物车只有 GET `/cart`、POST `/cart/items` 和 POST `/cart/merge`，因此界面可以保留删除/数量布局，但不能在缺少对应接口时宣称真实写入成功。
